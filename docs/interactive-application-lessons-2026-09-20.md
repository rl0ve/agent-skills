# Reusable lessons from an interactive application build

Reviewed September 20, 2026. This update retains generic decisions from observed
implementation and review failures. It does not publish project content, personal
research, account information, credentials, recordings or a learner-study result.

## Decisions

| Observation | Decision and owner | Boundary |
|---|---|---|
| A shared scene handler could be cleared by the outgoing activity after its replacement was installed. | Adopt transition ownership and A → B → A checks in UI Router's motion guidance. | Shared resources only; no prescribed framework or global event architecture. |
| Imported parts affected container bounds; visible object categories and contents needed different meanings. | Adopt task/asset contracts, complete action validation and settled-result inspection. | Task-driven scenes, simulations and configurators; no assessment machinery for a decorative scene. |
| Clip generation, caching, transcription and playback established different facts. | Add a conditional reusable-clip reference to Voice Narration. | Does not claim new adapters, a budget-cap implementation or a listening-quality winner. |
| Broader content and passing implementation checks left a core fidelity requirement unmet. | Add a priority check at long-task phase boundaries. | Preserve the user's full outcome; neither stop at a prototype nor create endless optional requirements. |
| A Codex marketplace version pin lagged behind both plugin manifests. | Align metadata and add a derived parity test. | Test an actual packaging invariant, not exact policy wording. |

Existing guidance already covers auditioning, current provider-route checks, secret
managers, bounded visual refinement, source/license review, human quality-review
limits, and device-specific evidence. Those rules are retained rather than duplicated
as new standalone skills. No model-ranking or universal realism/learning claim follows
from the project experience.

## Manual policy walkthroughs

These are parent policy consistency checks, not independent agent trials, new runtime
tests or measured customer outcomes.

| Applicable request | Expected decision |
|---|---|
| A training simulation offers several tools and asks for one precise operation. | Map visible tool meaning to stable identity and validate tool, target, operation and state together. Report helped performance separately if claiming independent ability. |
| An instruction permits any chair but the world contains two chairs and a bench. | Accept either chair; do not equate a different category with the requested object. |
| A container asset includes a detached lid and alternate variants. | Choose active parts before bounds/anchors, then inspect an actual placement after animation settles. |
| Switching scene activities during speech leaves clicks dead or credits the new item. | Verify handler ownership and request/activity identity through switching, cancellation and replay. |
| An authorized batch has a spending ceiling and a paid call times out. | Keep its reservation; inspect status/cost before retrying. Include checks and retakes in the same ceiling. |
| A clip changes voice or language while its content ID stays the same. | Invalidate that recording identity; preserve other cached clips and verify the delivered file. |
| A transcript nearly matches but omits a negation. | Keep it out of the approved pack; similarity alone cannot accept it. |
| A prototype doubles its catalog while still missing the requested rendering quality. | Make the next phase address the fidelity bottleneck rather than treating breadth as acceptance. |

Nearby cases that should stay direct:

- A static form spacing edit needs no scene contract, input-mode matrix or audio ledger.
- A decorative still needs no object manipulation or learning-progress evidence.
- One already approved voiceover uses the ordinary narration route; do not build a
  reusable application player for it.
- A game without assessment claims needs correct actions, not a vocabulary scheduler
  or delayed-retention study.
- A completed narrow change should close after its affected checks; the phase guidance
  does not authorize more features, a model change, agents or a background goal.
