# Review-page verification

Run these checks against the final artifact. Record project-specific outcomes outside the reusable skill.

1. Match each image to its version, state and revision. Check the signature visual named by the user is plainly visible; inspect it directly.
2. Decode every embedded image. Inspect representative overview, detail, distinctive visual and mobile sections at delivered dimensions.
3. Test all filters and restore all-views mode. Test hiding and restoring versions; prevent a silently empty comparison.
4. Open an image, navigate if supported, switch fit/original size, close by button and Escape, and verify keyboard focus returns to its opener.
5. Test narrow width and desktop-to-mobile-to-desktop resizing. Check that content stays within its container and metadata remains readable. Exercise controls at each size.
6. If comments exist, test export/import and state-retention claims. Validate imported version IDs and text; never execute imported content.
7. For an offline file, disable networking and open the final single HTML file. Verify media, fonts and controls without sibling assets or CDN requests.
8. For a hosted preview, open the returned deployed URL and repeat the main comparison flow. Local checks do not prove hosting succeeded.
9. Confirm every absent capture has an explanation and each historical or proposed image is labeled. Verify that crops and content mismatches are disclosed.
10. Deliver one primary comparison artifact. Preserve originals and the manifest in the consuming project; avoid making the user reconstruct the review from many attachments.

## Trigger and boundary examples

Should trigger:
- "Show the three branches together so I can choose what to keep."
- "I remember a globe in the old build. Where did it go?"

Should not trigger alone:
- "Invent three new homepage directions." Use design exploration.
- "Write a keynote storyboard." Use capability storytelling.
- "Triage these copy issues one by one." Use guided assessment.

## Failure remedies

- Flat-map captures hide a globe elsewhere: inspect the opening and alternate modes, then add a distinct globe section.
- A collage makes screenshots unreadable: retain originals and offer an enlargement view.
- One branch contains several approaches: identify entry paths and pin each implementation.
- The host cannot deploy: disclose the failure and provide an authorized standalone-file fallback; never claim a local path is a live preview.
- The user prefers parts of different versions: record those parts separately; do not select a universal winner or revert code automatically.
