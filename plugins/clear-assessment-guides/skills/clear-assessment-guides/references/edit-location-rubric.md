# Choose a review copy or the original

Explain the location choice briefly with the issue. Honor the user's explicit target
and editing/saving roles; this rubric supports judgment, not a universal approval gate.

| Situation | Default |
|---|---|
| Unsettled wording, alternatives or substantive layout/HTML changes | Review copy or local proposal |
| Rendering, responsive behavior or interactions need testing | Review copy in the actual destination when available |
| Proposed replacement asset or new product/pricing/legal claim | Resolve the evidence/owner question first, then review the proposal |
| One settled typo, display-label correction or verified link repair | Original if the conditions below are satisfied; otherwise copy |
| Result already reviewed in a copy | Original within the authorized application scope, after checking intervening edits |
| Permissions, shared navigation, archives or managed source-asset changes | Separate the exact action from page edits; follow the user's authorization for that scope |

A direct original edit is reasonable when the change is settled, bounded to a known
field/block, and its save and recovery behavior is understood. Capture the before
state and exact text/URL. Verify that the original has not changed in the meantime.
For a trivial fix, manual restoration may be sufficient; native version rollback is
not always necessary. Do not infer rollback after saving from an Undo control.

If editing before Save is intended, establish whether autosave or publication can
occur and whether unsaved changes can actually be discarded. A visible Preview button
alone proves neither. Unknown behavior favors a copy or external proposal. User
instructions can authorize another approach; communicate material remaining uncertainty.

Before creating a native copy, inspect destination and visibility when the UI permits.
Use a suitable existing location within the authorized scope. Verify a distinct ID,
save, reopen, and check editability and inherited access. Never call a copy a private
draft based only on its name. Do not change sharing to make it private without the
necessary authorization. If storage/access cannot be established and consequences
matter, use a local proposal until that question is resolved.

Before applying a reviewed result to the original, compare the affected area with its
baseline and preserve intervening work. Apply only agreed changes; verify the actual
saved result and affected links. Keep exact prior values for recovery. For a large
rebuild, investigate supported transfer/version mechanisms before accumulating manual
rework. A copy does not establish a native compare/merge feature.
