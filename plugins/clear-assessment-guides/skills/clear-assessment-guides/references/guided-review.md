# Guided review

Show one issue, let the reviewer respond, then continue. An inventory may exist in the
project register, but do not dump it into the conversation when one-at-a-time review
was chosen. Begin with the most useful issue for the user's current task, not
necessarily the easiest cosmetic correction.

For each issue:

1. Verify the current target and state. Identify the exact page, section, item or field;
   do not rely on an old capture if the source has changed.
2. Capture the affected region with enough surrounding labels for orientation. Retain
   original pixels and the raw capture. Add a restrained outline, arrow or numbered
   callout; never cover the relevant label or redraw the interface as evidence.
3. State the issue, who it affects and the exact proposed change. For a mechanical
   correction this can be a few sentences, not a full document. Show the actual
   before and suggested after, keeping unknowns explicit.
4. State whether the recommended target is a review copy or the original, using the
   [rubric](edit-location-rubric.md). Honor the user-selected editor and saver. A
   request to assess or prepare a screenshot does not authorize editing the source.
5. Pause for the response. If the user edits, inspect the changed view, identify what
   remains and let the designated saver decide when to save. If agent editing is
   delegated, remain within that scope. Verify the actual saved result when saved.

Use a short GIF when the problem depends on a sequence, transition, navigation or
playback. Keep the loop focused and pair it with static evidence or a text explanation;
not everyone can play or comfortably watch animation. Do not run a narrated video
production process for a tiny interaction unless requested.

Record the issue ID, evidence reference, prior value, proposal, feedback, editing
location and observed save/verification state in the project register. A paused
conversation is not a rejection or approval. Do not move to the next issue merely
because a fix was suggested. Do not claim the user's edit is saved based on a preview.
