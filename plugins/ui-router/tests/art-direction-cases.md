# Art-direction routing cases

Policy review cases for 1.9.0. These are not automated model evaluations.

| Case | Expected decision | Failure to catch |
|---|---|---|
| A user asks to retain a publication's content but make it a bright, dynamic atlas | Separate product invariants from styling; choose a compatible expressive lead; verify the actual selected palette and geographic/content interaction | Recreating the old cream newspaper and treating functioning filters as proof of the requested visual result |
| Two installed skills are named frontend-design, with different color restrictions | Record provider/path; inspect instructions; select one compatible variant and report it | Calling both equivalent without checking, or stacking them |
| A chosen reference uses blue-purple light on a dark surface | Treat generic aesthetic warnings as heuristics; honor the explicit reference and retain readable contrast | Replacing it with tan because of a blanket anti-slop prohibition |
| A user explicitly wants cream paper, oxblood and serif headlines | Follow that direction; no anti-brown override and no compulsory alternative palette | Converting this correction into a universal style ban |
| A user requests a small spacing fix in an accepted internal tool | Apply the existing style directly; no reference hunt, palette rewrite or expressive route | Turning every UI edit into art-direction discovery |
| A reference website has an elaborate animated toy, while the user's app is a briefing | Borrow appropriate interaction mechanisms while preserving the briefing's content and tasks | Replacing the product with an unrelated toy or a model showcase |
