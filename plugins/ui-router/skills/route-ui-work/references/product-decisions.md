# Find the decision before polishing the screen

Use when a redesign, confusing flow or disagreement about the product has no clear
visual cause. For a defined spacing, color, animation or copy edit, preserve the agreed
behavior and do the requested work directly.

Read the available brief, interface and evidence first. Identify the unresolved
decision that changes the design, rather than asking every possible discovery question.

| Signal | Work to do | Evidence or decision to retain |
|---|---|---|
| The proposed improvement assumes what users need | Check observations, analytics or supplied research; label assumptions | The task and evidence supporting it, plus the specific unknown |
| The same term means different things, or object states are unclear | Clarify objects, relationships, names and state changes | A short model or state map only if it resolves the ambiguity |
| Users cannot predict where an action leads or recover from failure | Work through the relevant journey and transitions | Expected result, failure recovery and unresolved behavior |
| The behavior is sound but hierarchy or legibility fails | Use the existing surface lead and targeted craft guidance | The observable visual problem and comparison after the change |

When an action has delayed effects, distinguish pending from confirmed success. Where
relevant, resolve refresh behavior, concurrent changes and deletion semantics at the
behavior level before choosing visual feedback. Use a prototype to test a hypothesis
when helpful; a convincing mockup does not turn that hypothesis into user evidence.

Keep the record proportional: the decision, its basis and any consequential uncertainty.
Do not manufacture a full seven-layer report, reopen settled product choices without
new evidence, or let an optional diagnostic block independent authorized work. Ask for
missing input only when it materially changes the result and cannot be inferred.

For a multi-phase build, apply Work Router's long-task guidance if available. Accept a
UI phase against its required behavior and visual evidence, then continue to the next
required outcome. Repeated cosmetic changes to an accepted region are not progress.

## Source and scope

Reviewed September 5, 2026. [Jamie Mill's Layers framework](https://layers.jamiemill.com/)
distinguishes the decisions beneath a screen from its surface. Its
[intro](https://github.com/jamiemill/layers-skills/blob/main/skills/layers-intro/SKILL.md)
and [orientation skill](https://github.com/jamiemill/layers-skills/blob/main/skills/layers-orient/SKILL.md)

sequence. This is a scoped routing adaptation; it neither installs the Layers pack nor
claims its remaining skills have been reviewed. If that pack is chosen, review the
selected instructions and dependencies before installation and read them before use.
