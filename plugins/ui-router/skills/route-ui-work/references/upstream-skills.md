# Use upstream specialists selectively

UI Router selects and coordinates. A selected upstream skill owns its detailed craft.
Use this reference when choosing an external workflow or deciding whether to load,
install or adapt one. Existing local capabilities and the user's explicit choice come
first; ordinary tasks do not need fresh repository research.

## Choose how to consume the skill

| Situation | Route |
|---|---|
| A distinctive specialist workflow fits this task | Load the original selected skill and its required references. Do not replace its procedure with a router summary merely because the summary is shorter. |
| A skill will be used repeatedly | Within install authorization, install its complete folder and required dependencies through the host's supported route. Select named skills, not an entire repository by default. |
| A small principle is useful across many tasks | Adapt it into the existing router concern with attribution, scope and evidence. Keep specialist procedures upstream. |
| The original conflicts with the task or host | State the specific conflict and the narrow override or fallback. Preserve unaffected craft; label a materially changed workflow as an adaptation. |

For occasional use, reading a retrieved skill as task context need not install it
permanently. A repository homepage is discovery evidence, not loaded instructions.
Read the complete selected SKILL.md and the supporting files required for this path;
inspect any scripts before executing them. Preserve relative links, sibling dependencies
and license notices when copying or installing. Do not pull a lone entrypoint out of a
package whose workflow requires the rest.

Record source URL, exact skill path, retrieved version/commit when available, and any
local changes. Report whether the source was merely catalogued, actually loaded, or
installed and verified. A file or lock entry alone does not prove current-session use.
Review upstream diffs when refreshing a selected dependency; do not silently overwrite
local adaptations or fetch every repository on every task. Source revisions make the
review reproducible; they are not a claim that the installed copy is current forever.
