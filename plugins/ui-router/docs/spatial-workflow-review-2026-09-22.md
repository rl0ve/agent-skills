# Spatial workflow review — September 22, 2026

This update generalizes observed implementation and browser-validation failures in an
interactive 3D project. It contains no private source archive, account status, learner
records or project artifacts. The cases below are policy exercises, not a new product
benchmark, native-language review or headset trial.

## Decisions

- **Adopt:** inspect task objects with the actual text/control panel visible; a correct
  world-space arrangement can still hide the object the user needs to see.
- **Adopt:** validate full placement chains and container interiors, including label
  facing and visibility, when changing art or supports.
- **Adopt:** record the scope and source of baked lighting/captures; distinguish changed
  dynamic objects from the static approximation and affected rebake dependencies.
- **Adopt:** compare equivalent graphics settings and paths, with competing previews
  removed and startup separated from steady-state measurements.
- **Conditional:** Hyper3D/Rodin is an asset-generation candidate. Official
  [MCP information](https://hyper3d.ai/features/mcp) and
  [Gen-2.5 documentation](https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5)
  were checked on September 22. Live MCP schemas exposed generation, status/wait,
  result retrieval and image-upload routes; generation uses credits, and connector
  restrictions govern result links/downloads. No generation or quality comparison was
  performed for this skill release. Account access and prices are not shared policy.
- **Already covered:** distinguish catalog/input counts, independent performance and
  measured human outcomes; prioritize the highest-priority unmet requirement.
- **Adopt in Work Router:** recover interrupted processes and provider jobs from live
  evidence and their original handles, without duplicate work or paid submissions.
- **Unchanged:** model/effort defaults, service tier, one-writer policy, specialist
  ownership, and user authorization. No new broad skill or mandatory tool was added.

## Applicable cases and nearby non-triggers

| Case | Expected decision |
| --- | --- |
| A container action changes state but the inserted label faces away below the rim | Inspect the settled task view; fix the physical/visible result and replay it. A state assertion alone cannot close the visual check. |
| A smaller table looks better with one cup but later beside-placements overhang | Validate the full arrangement before accepting the replacement surface. Preserve the semantic sequence. |
| A side panel obscures the target after an otherwise valid placement | Scope the object/camera composition change and reset it outside this activity; keep required text readable. |
| New fixed joinery changes a room with baked lighting and reflections | Inspect the exported dependency set; refresh affected derived assets or explain the supported approximation. |
| A new decorative prop is outside the capture's influence | Do not impose a whole-world rebake without evidence of an affected dependency. |
| A connected generator offers a high-poly candidate | Check the live route and authorized credit use; trial one asset and validate it in the destination. Do not assume XR readiness or bulk-generate by default. |
| A generation wait times out with a valid job ID | Poll that job; do not submit another generation. An ambiguous initial submission follows provider recovery instructions. |
| An interrupted preview's old port is absent but the process poll merely timed out | Inspect the original handle or authoritative process state before replacing it; a timeout alone is inconclusive. |
| A button label changes in an accepted scene | Check the affected label/layout. Do not reopen asset research, generation, baking or profiling. |
| A decorative still is requested | Judge the requested image. Do not invent manipulation, collision, saved state or headset requirements. |

Policy review found these routes consistent with current scope, permission, specialist
and single-writer rules. Package validation is recorded with the release; no synthetic
case is presented as evidence of improved human engagement or rendering performance.
