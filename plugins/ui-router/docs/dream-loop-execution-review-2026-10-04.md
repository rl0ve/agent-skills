# Dream Loop execution gate - October 4, 2026

## Decision

Adopt an explicit completion gate for substantial 3D work whose acceptance depends
on requested high graphical fidelity. UI Router owns this correction; Work Router's
model, ownership and permission rules are unchanged. Existing links and loading
instructions did not by themselves require a record showing that the loop ran.

The maintained [gate](../skills/route-ui-work/references/upstream-skills.md#fidelity-execution-gate)
distinguishes listed, loaded, executed and accepted. It preserves original workflow
selection and criteria, while requiring explicit evidence and unresolved gaps.
Ordinary edits stay direct. A materially adapted workflow keeps its own name and
scope rather than inheriting an upstream completion claim.

Target authoring is explicit: use the host Imagegen tool within authorization when
no target is supplied, and include the existing product's running baseline and
semantic constraints. World-map targets use actual destinations and routes with
readable navigation, not invented progress or clickable future environments.
Retain prompt, selected output and identity for the implementation comparison.

## Applicability Checks

These are manual policy walkthroughs, not independent agent trials or rendered builds.

| Case | Expected result |
| --- | --- |
| Substantial scene requested at high graphical fidelity | Select the full workflow unless the user chooses another method; retain evidence for every execution gate. |
| Dream Loop exists only in a resource catalog | Report listed, not loaded, executed or accepted. |
| Workflow read and implementation builds, but no live comparison exists | Loaded only; rendered comparison remains open. |
| Builder grades its own screenshot | Do not call this fresh-context critique or independent acceptance. |
| User or host disallows subagents | Do not delegate; mark the fresh-review gate open and identify any explicitly selected adaptation. |
| No target or authorized image-generation route | Mark the target gate blocked; no automatic paid fallback or easier target. |
| Existing adventure needs a world-map target | Supply its current capture and real route/state constraints to Imagegen; lock the selected product-specific output before implementation. |
| A generated map has attractive but fictional destinations or unreadable controls | Correct the target within the agreed brief; do not import invented travel state or flatten real controls into an image. |
| Optimization changes visible water or vegetation | Capture and rejudge affected appearance before acceptance; retain device-specific runtime evidence. |
| Strong visual verdict but required UI or accessibility checks remain open | Keep those independent gates open; do not claim full completion. |
| User selects a bounded parent-only comparison | Label the router adaptation and its scoped result, not full Dream Loop completion. |
| A form label or unrelated state bug needs a correction | Use the existing owner and focused checks; no fidelity loop. |

Package, link and metadata checks validate publication structure only. They cannot
prove that future builders follow this policy or that it improves rendered fidelity.
